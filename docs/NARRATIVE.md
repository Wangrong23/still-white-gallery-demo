# 白厅文案底稿（开发用，不在游戏里展示）

## 故事的牵连

1934 年，市政会计遇害，一页付款记录失踪。会计生前去过白厅，也与灰衣来客有过约定。警探循着目击线索到馆；来客仍在等人，身上带着一张不肯交出的纸。白厅仍在办展，匿名借展的标牌与六件人像目录都保留。

账页、会计的死与警局之间存在待查的关系，但不把“上司的名字就在账页上”作为已确认事实。来客衣袋里的纸是否就是账页、赴约要交付还是索取什么、警方到场意味着保护还是危险，都不由结算宣布。这里也不替任何一方补出无辜证明。此前临时加入的“两封匿名信、一个签名”设定撤下。

警探相信灰衣人把他带到了案子的下一步，注意衣领上的石膏粉、去向和同僚。来客在等一个没有出现的人，注意警探的枪、脚步、自己会不会被听见。两人的判断各自有生活中的理由，不让他们向玩家争辩谁先动手。

## 玩家看到的顺序

菜单只交代死讯与画廊照常营业。准备阶段给当前角色一段够用的处境；白天提示回到眼前的脚步与搜寻。日落后的目标仍清楚告知追捕、伏击、南门和支援时间。

结算正文停在这一局结束附近的感官经验。支援抵达时，警探看见熟人；来客听见有人亲切地叫警探的名字。同一个事实对双方产生不同意义，正文不解释这种差异。胜负和结束原因放在独立的短标签里。

不要再用“双方陈述”“真相”“你以为”“其实”替玩家总结主题；不要每段都埋反转。小幅黑色幽默来自庄重展馆里狼狈的人，而非连续的漂亮警句。结算不得编造玩家未做的举手、开枪、台词；尤其识破可能来自检查或射击，两者共用的结算不能擅自宣告死亡。

中英文的实际游戏文案分别维护在 client/i18n.js 和 client/narrative.js；此文件是写作约束，不是额外的玩家读物。
